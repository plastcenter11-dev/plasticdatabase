# تشغيل البرنامج على سيرفر والفروع تدخل عليه من الإنترنت

## الفكرة
```
متصفح الفرع  ──HTTPS──▶  Caddy (80/443)  ──▶  البرنامج (127.0.0.1:3001)  ──▶  MySQL (localhost فقط)
```
- الفروع **مش بتثبّت حاجة**: بتفتح رابط السيرفر في المتصفح وبتسجل دخول.
- المنفذ 3001 وMySQL (3306) **ممنوع** يتفتحوا على الإنترنت. المفتوح بس 80 و443.
- كل الفروع بتشتغل على **نفس قاعدة البيانات** (مفيش مزامنة بين قواعد بيانات).

## قبل ما تفتح للإنترنت (إلزامي)
1. **دومين** يشاور على عنوان السيرفر العام (أو خدمة نفق زي Cloudflare Tunnel لو مفيش IP ثابت).
2. **مستخدم قاعدة بيانات محدود:** شغّل `deploy/mysql_app_user.sql` بعد تغيير كلمة السر، وحط المستخدم الجديد في `backend/.env` بدل `root`.
3. **MySQL على localhost فقط:** في `my.ini` خلّي `bind-address=127.0.0.1`.
4. **ملف `.env` للإنتاج:** انسخ `deploy/env.production.example` إلى `backend/.env`.
   - `JWT_SECRET` لازم 32 حرف عشوائي على الأقل (البرنامج بيرفض يشتغل في الإنتاج لو أقل).
   - `NODE_ENV=production` و`TRUST_PROXY=1`.
5. **جدار الحماية (Windows Firewall):** اسمح بـ 80 و443 فقط من الإنترنت.
6. **غيّر كلمة سر الأدمن** من أول دخول (8 حروف على الأقل). البرنامج مابقاش بيعمل `admin/admin`: بيطبع كلمة سر عشوائية مرة واحدة أول تشغيل على قاعدة فاضية.

## التشغيل
```bash
cd frontend && npm install && npm run build      # بيطلّع frontend/dist ويقدّمه البرنامج بنفسه
cd ../backend && npm install && node server.js
```
**كخدمة ويندوز** (بتشتغل لوحدها وتعيد التشغيل لو وقعت) بـ [NSSM](https://nssm.cc):
```
nssm install PlasticDB "C:\Program Files\nodejs\node.exe" server.js
nssm set PlasticDB AppDirectory D:\plasticdatabase\backend
nssm set PlasticDB AppStdout D:\plasticdatabase\logs\app.log
nssm set PlasticDB AppStderr D:\plasticdatabase\logs\app.err.log
nssm set PlasticDB Start SERVICE_AUTO_START
nssm start PlasticDB
```
**Caddy** (الـ HTTPS): حمّله من caddyserver.com، حط `deploy/Caddyfile` بعد تغيير الدومين، وشغّله كخدمة (`caddy run --config Caddyfile` أو `caddy add-package`/NSSM).

## الأمان المتوفر في الكود
- محاولات الدخول: 5 غلط لنفس المستخدم من نفس العنوان = قفل 15 دقيقة، وحد أقصى 40 محاولة لكل عنوان.
- تغيير كلمة السر بيقفل كل الجلسات القديمة.
- التوكن ساري 12 ساعة (`TOKEN_LIFETIME`).
- رؤوس أمان للمتصفح، وكل ردود الـ API مش بتتخزّن في الكاش.
- أخطاء قاعدة البيانات بتتسجل في السجل بس، ومابتظهرش للمستخدم.
- سجل العمليات (من عدّل أو حذف إيه ومتى) بيسجل عنوان الـ IP الحقيقي لما `TRUST_PROXY=1`.

## النسخ الاحتياطي
- النسخة اليومية بتتعمل لوحدها (المهمة المجدولة). اختار مكان **نسخة ثانية خارج السيرفر** من الإعدادات ← نسخ احتياطي.
- جرّب الاسترجاع كل فترة: `npm run verify:backup` من فولدر `backend`.
- مكان النسخ **لازم** يبقى على جهاز تاني أو سحابة، مش على نفس القرص.

## التحديث
1. خد نسخة احتياطية الأول (الإعدادات ← نسخ احتياطي ← نسخ احتياطي الآن).
2. أوقف الخدمة، `git pull`، `npm install` في الفولدرين، `npm run build` في frontend.
3. شغّل الخدمة وراجع `npm run check:invariants` من فولدر backend (لازم 0 أخطاء).

## مش هتنفع
- تشغيل `vite` (وضع التطوير) على الإنترنت.
- فتح 3306 أو 3001 على الراوتر.
- تشغيل البرنامج بمستخدم `root`.
- ربط الفروع بمزامنة قواعد بيانات: الأرصدة والترقيم هتتعارض.

## لو النت فصل عند فرع
- الفرع **مش هيقدر يشتغل** (البرنامج على السيرفر). جهّز خط إنترنت احتياطي للفرع والمقر، وخطة ورقية مؤقتة (إذن تسليم ورقي يتسجل بعد رجوع النت).
- UPS للسيرفر والراوتر.

## تنصيب وتحديث تلقائي على ويندوز (بدل الخطوات اليدوية)
من PowerShell كمدير (Run as administrator) داخل فولدر المشروع:

- **تنصيب السيرفر (مرة واحدة):** `powershell -ExecutionPolicy Bypass -File deploy\windows\install-server.ps1`
  يبني الشاشات، يجهّز `backend\.env` للإنتاج (مفتاح JWT عشوائي لو أقل من 32 حرف، ومعاه نسخة من القديم)، يسجّل مهمة "PlasticDB Server" تشتغل مع الجهاز وتعيد نفسها لو وقفت، يمنع النوم، ويفتح المنفذ 3001 لشبكة Tailscale فقط (100.64.0.0/10). مفيش أي تغيير في محتوى القاعدة.
- **تحديث السيرفر:** `powershell -ExecutionPolicy Bypass -File deploy\windows\update-server.ps1`
  يرفض لو في تعديلات غير محفوظة، ياخد نسخة احتياطية، يوقف، يسحب آخر نسخة من GitHub، يبني، يشغّل، ويفحص السلامة والأرصدة. لو النسخة الجديدة ما اشتغلتش بيرجّع القديمة تلقائياً. `-DryRun` يعرض اللي هيحصل من غير تنفيذ.
- ثبّت Tailscale على السيرفر وعلى كل فرع وعلى الموبايل، وافتح `http://<عنوان Tailscale للسيرفر>:3001`.

## ملف التنصيب PlasticDB-Setup.exe (لتجهيز سيرفر جديد على جهاز آخر)
- يبنيه `ISCC.exe deploy\windows\PlasticDB-Setup.iss` (برنامج Inno Setup مجاني)، والناتج في `deploy\windows\Output\`.
- لازم الجهاز الجديد يكون عليه **Node.js (LTS) و Git و MySQL Server 8** (الـ Setup بيفحصهم ويديك الروابط لو ناقص واحد).
- بيسأل عن مكان التنصيب (الافتراضي `C:\PlasticDB`) وعن باسورد `root` بتاع MySQL. بيستخدمه مرة واحدة ليعمل قاعدة البيانات والمستخدم المحدود `plasticdb_app` ولا بيحفظه.
- بينزّل آخر نسخة من GitHub، يجهّز `backend\.env`، يشغّل `install-server.ps1`، ويسجّل مهمة النسخ الاحتياطي اليومي الساعة 1 صباحاً.
- في الآخر بيعرض أول تسجيل دخول (`admin` وباسورد عشوائي) ومحفوظ في `first-login.txt`: امسحه بعد ما تدوّنه.
- التحديث بعد كده بـ `update-server.ps1` زي ما هو.
